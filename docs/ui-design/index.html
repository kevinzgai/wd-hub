四版 240×320 看板，同一套状态与三键规则

同一份业务数据（会话列表、审批、提问、待机、离线、低电量）用四种视觉语言各做一套。 所有画布严格 240×320、四周 12px 安全区；正文只用 12 / 16 / 28 三档字号；所有描边 2px 起， 不使用细发丝线；状态不靠颜色单独表达，永远带文字。默认 2× 显示，可切 1× 或开启 50% 背光模拟。

画布

240 × 320 px 竖屏，左右 12px、上下 10/12px 安全区。内容宽度 216px。

字号与每行字数

12 / 16 / 28 点阵。216px 内：12px ≈ 18 汉字，16px ≈ 13 汉字，28px ≈ 7 汉字；ASCII 约半宽。

按键

UP / OK / DOWN，长按 800ms。无触摸、无滑动。焦点必须可见，键位提示必须在屏上。

背光假设

长期 50% 背光。正文对比度按 ≥7:1 设计（不是 WCAG 的 4.5:1），避免中灰大面积与低对比小字。

设计说明

1. 三键交互（四版共用一套语义）

页面UPOKDOWN长按（800ms）
会话总览焦点上移打开当前会话焦点下移长按 OK：刷新会话
审批命令原文上滚允许执行命令原文下滚长按 DOWN：拒绝；长按 OK：看全文
提问选项上移确认作答选项下移长按 OK：展开全文
待机唤醒唤醒唤醒长按 OK：直接回总览
离线查看缓存立即重试查看缓存长按 OK：回总览
低电量暂时屏蔽返回总览暂时屏蔽长按 OK：关闭本次提醒

审批页遵循需求里的“长按 DOWN 拒绝”；允许是短按 OK。危险动作不依赖触摸，也不依赖滑动。所有页面底部都保留三键提示，焦点永远有边框/色块/左轨三种之一的明确表达。

2. 溢出、截断与滚动

  • 总览最多 6 条：V1 / V3 / V4 显示 4 条 + “还有 N 条”，焦点越过第 4 条时整屏上滚一行；V2 一次一条，用 3 段进度表示位置。没有独立滚动条，避免 2px 竖条在 50% 背光下变成脏线。
  • 会话名：16px 单行，超出用省略号。V1 卡片内约 10 个汉字，V2 / V3 / V4 约 13 个汉字（V4 有编号列，约 11 个）。
  • 模型名：12px，最长约 18 个 ASCII；超长用尾部省略。主机侧按协议上限截断，设备只做二次兜底。
  • 命令原文：12px 等宽，216px 宽约 36 个 ASCII/行；V1 / V2 / V4 显示 4 行，V3 显示 5 行，超出用省略号；长按 OK 展开全文。
  • 问题：16px，约 13 个汉字/行；最高 3 行（V1）或 2 行（V2/V3/V4），超出省略，长按 OK 看全文。
  • 选项：16px 单行，最多 6 项；一屏显示 4 项 + “还有 N 个选项”，焦点跟滚。

3. 50% 背光下的可读性判断依据

WCAG 对比度是相对亮度比，均匀降低背光不会改变比值，但会降低绝对亮度、压缩人眼在低亮度下的对比敏感度。因此本稿不按 4.5:1 的网页标准，而按 正文 ≥ 7:1、次要文字 ≥ 7:1、强调色 ≥ 7:1 设计；并且不使用中灰大面积、不使用 1px 细线、不把状态只交给颜色。

版本主文字 / 背景次要文字红色强调深字压亮底额外约束
V1 卡片台16.0:18.7:17.2:111.5:1（绿底）卡片之间用 2px 描边 + 6px 间距，不靠中灰填充区分
V2 大字流19.3:18.1:17.2:113.0:1（薄荷底）纯黑底，未选中项也保持 8.1:1
V3 仪表盘16.2:18.7:17.4:18.2:1（红底）KPI 用 28px 数字，避免 12px 小字承担关键数字
V4 护照印章16.5:19.8:17.4:111.6:1（绿底）所有装饰线 2~3px；印章文字 16px 起

补充：V1 的红色用于「待审批 / 出错 / 拒绝」等语义，不用于选中卡上的正文（选中卡用深底反白 + 青边，13.7:1），避免红色在较亮的选中底上掉到 6:1 附近。

4. 推荐版本

推荐 V1「卡片台」作为主方案。理由：240×320 比现有 240×240 多出 80px，刚好把会话卡从 2 条提升到 4 条；日常最高频的动作是“看有哪些会话、哪条要审批”，V1 用最少的按键完成，4 条可见 + 焦点滚动比 V2 的一条一翻更省操作。它的 16px 名称、12px 元信息、2px 边框在 50% 背光下分别是 16.0 / 8.7:1，且延续现有产品的深海军蓝 + 青色语言，移植和验收风险最低。

  • V2：单条最大可读性最好，但 3 条会话最多要按 2 次 DOWN；适合“只看当前一条”的展示/挂墙场景，不适合高频操作。
  • V3：时钟与全局统计最顺手，但 29px 会话行在 50% 背光下对 12px 状态字要求较高；适合桌面时钟定位，需要再增加一档“放大当前行”的交互才适合做主界面。
  • V4：品牌感最强，但护照抬头、印章、编号占用了本可以给数据的像素；适合展示/礼品版本，不建议作为高频工作看板。

5. 落地注意（给固件 / 主机同学）

  • 字符集：屏上固定文案只使用现有 12 / 16 / 28 三档字库已有字符；V4 的 RUNNING / APPROVAL / QUESTION / STANDBY / NO SIGNAL / LOW POWER 只用标准大写 ASCII，不新增汉字。若「签证」「护照」等新词不在字库，按 gen_charset.py → gen_fonts.py 流程补字后再编译，不在运行时硬编缺字。
  • 页面复用：待机页沿用现有复用结构，进入时一次性完整渲染，退出不影响正式页面；只在时间/状态变化时局部刷新，不做呼吸、闪烁、滚动动画，符合省电约束。
  • 列表实现：V1 / V3 / V4 只保留 4 个可见行 + 1 个溢出行，焦点越过边界时整屏上滚；不要为 6 条数据创建 6 套完整卡片对象，减少 LVGL 对象数与重绘面积。
  • 按键：UP / OK / DOWN 短按与 800ms 长按沿用现有消抖逻辑；审批页「长按 DOWN 拒绝」需要长按判定，不与短按 DOWN 的滚动冲突。长按 OK 统一让给底座电源语义（2s 提示 / 5s 关机），不承载页面功能。
  • 背光与档位：本设计默认运行在 50% 背光；待机沿用现有低功耗档位（背光 50%、LVGL 低帧率、BLE 长连接间隔），不在本稿里改待机门槛与唤醒逻辑。
  • 低电量：建议阈值 15%，仅在放电且 SOC ≤ 阈值时覆盖显示；OK 返回上一页、长按 DOWN 关闭本次提醒，充电后按 SOC 回升自动解除。
  • 渲染校准：本文件是浏览器预览，用系统字体近似点阵字；实机 12 / 16 / 28 点阵的字宽、行高与省略号位置需在 LVGL 上逐页对照截图校准，尤其是 28px 时间的字距和 V4 旋转印章的边界。
  • 未做部分：没有修改任何固件、主机代码，也没有提交到 main；没有在实机上跑这四版，只交付可打开的 HTML 设计稿与说明。
