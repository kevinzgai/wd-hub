# 提示音「听不见」根因与修复报告（2026-11-03）

> 设备：ESP32-C3，MAC `98:C3:77:F4:49:00`（BLE `98:C3:77:F4:49:02`）
> 结论依据：用户实测（长音诊断「有声音了」）+ 串口日志 + ES8311 寄存器回读
> 未碰 `firmware/`、未碰 `main`；临时诊断钩子已移除，本次只编译、未烧录

## 一、结论

**断在“音量档位 + 二次衰减”，不是功放、codec 静音、I2S 格式或采样率。**

| 排查项 | 判定 | 证据 |
| --- | --- | --- |
| 是否根本没播 | **否，播放执行了** | 每次注入都有 `wb_audio: 播放 ATTENTION ... 累计 played=N`，`played` 单调递增；诊断长音期间 `bsp_audio_write` 无失败日志 |
| codec 是否静音 / 未上电 | **否** | 诊断时回读 `REG00=0x80`（正常上电）、`REG0D=0x01`（DAC 上电）、`REG31=0x00`（DAC 未静音）、`REG44=0x08` |
| 输出音量是否接近 0 | **是，这是根因** | 100% 档回读 `REG32=0xD2` ≈ +9.5dB；原 20% 档按 BSP 曲线只有 -42dB，再乘 PCM 的 20% 软件增益（-14dB）≈ **-56dB**，等同静音 |
| I2S 格式 / 采样率 | **否（但有一处不一致，见残留风险）** | 日志 `STD: TX, 16bit, 16kHz, mclk 256`；`slot_mode: MONO, slot_mask 0x1`，与“16kHz/16bit”一致 |
| 功放 / 喇叭供电 | **否，硬件正常** | 同一颗 codec、同一路 I2S，仅把音量从 20% 提到 100%，用户即听到 2s 长音 |

一句话：**软件把音量压了两遍**——codec 档位 20%（曲线落点 -42dB）＋ PCM 再乘 20%（-14dB）；合计约 -56dB，任何人耳都听不见。长音诊断绕过这两层后用户立即听到，证明 codec、功放、喇叭整条链路是通的。

### 关键证据（诊断轮，串口原文）

```

I (30038) bsp_audio: 主音量=100%, 应用=20%, 输出=20%
I (30040) wb_audio: DIAG 长音开始: codec 100%, 主音量临时 100%, 2000ms 满幅 1kHz

```

对比原正式构建：`codec 就绪: ... 固定音量 20%`，`主音量=80%, 应用=20%, 输出=20%`。

## 二、修复内容（已并入正式构建）

`passport-fw/main/wb/wb_audio.c`：

1. `WB_AUDIO_VOLUME` 由 `20` 改为 `100`。语义改为 **codec 档位**，响度由系统主音量（默认 80%）决定：有效 80% ≈ -6dB。
2. 删除 `play_one()` 里的 PCM 软件增益 `* (WB_AUDIO_VOLUME / 100.0f)`，PCM 满幅写入，不再二次衰减。
3. 临时诊断钩子全部移除：`wb_audio_diag_tone()`、串口 `x`（100% 长音）/`z`（寄存器回读）、`bsp_audio_dump_regs()` 及其头文件声明。

为什么定 100：
- 20% 档位在这块板的 BSP 曲线上是 -42dB，本身就偏低；
- 100% 档位在系统主音量 80% 时约 -6dB，比 S3 的 `AUDIO_VOL_DEF=20%`（≈-14dB）响一档，能保证 700ms 的 ATTENTION 在环境噪声下被听到；
- 用户侧仍可用系统主音量（默认 80%）整体调小声，不必改代码。

## 六、残留风险

1. **I2S 通道声明与写入不一致**：日志为 `slot_mode MONO, slot_mask 0x1`，而 `play_one()` 写的是 L/R 交错立体声。用户听到的长音是“有声”，但**未确认音调/时长是否准确**（理论上可能低八度、时长翻倍）。本轮未改，避免在无法复听时动已验证可出声的路径。
2. **真实场景 700ms ATTENTION 尚未用耳朵验证**，只验证了 2s 长音。
3. **音量 100 的主观合适度未定**，需下次开机用耳朵确认后再决定是否回落到 80~90。
